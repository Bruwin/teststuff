# Session 006 -- M3b: OpenGL backend and screenshot capture

**Date:** 2026-11-07
**Milestone:** M3b (hardware path)
**Outcome:** `verify: OK`, 55 tests, 0 findings. One file remains CI-only.

## The constraint that shaped the design

The GL backend must not include `<GL/gl.h>` or SDL: there is no driver here, and
more importantly `MOD-03` forbids SDL above `platform/`. Those two rules turned
into the architecture rather than fighting it:

| Layer | Owns | Compiles here |
|---|---|---|
| `rhi/gl/gl_api.h` | GL types and entry points, declared by hand | yes |
| `rhi/gl/gl_loader.cpp` | name -> function pointer, through a callback | yes |
| `rhi/gl/gl_device.cpp` | the device and swap chain, replaying `CommandBuffer` | yes |
| `platform/gl_context.{h,stub.cpp}` | "there is no context" | yes |
| `platform/gl_context_sdl.cpp` | SDL context creation, proc addresses, swap | **no** |

The device talks to a table of function pointers, so the fake table in the tests
drives the real upload/draw/capture code. Only context creation is unverifiable
here, and it is 80 lines.

## What shipped

- `rhi/gl/gl_device.{h,cpp}` -- VAO, one dynamic VBO per frame, 4.60 core shaders
  (8 floats per vertex: clip-space position + unpacked colour), `glDrawArrays` per
  primitive, `glReadPixels` capture.
- `rhi/gl/gl_loader.{h,cpp}` -- asks for all 28 entry points by name and reports a
  short table instead of crashing later.
- `rhi/capture.h` -- `CapturedFrame`, always top row first.
- `platform/gl_context*` -- core-profile 4.6 context on the window handle.
- `render/ppm.{h,cpp}` -- binary PPM writer.
- `--screenshot <path>` on both modes: hardware readback when a surface exists,
  reference rasteriser when it does not. Same file format either way.

## Decisions worth keeping

1. **Capture is `const`.** Reading the surface does not change it, and the app holds
   the chain by pointer-to-const in the screenshot path.
2. **Readback is flipped once, at the boundary.** GL returns the bottom row first;
   `CapturedFrame` and every writer above it are top row first, so the flip happens
   in exactly one place and a test pins it (row 0 of a 2x3 capture carries GL row 2).
3. **PPM, not PNG.** A screenshot has to be inspectable without a dependency: P6 has
   a five-line header and a test can read it back. A PNG encoder in the engine would
   be a third-party dependency (`MOD-05`) for no gameplay value.
4. **A GL failure degrades, it does not abort.** No context, incomplete table, or
   shaders that will not link all fall back to the headless device with a log line,
   so the same binary runs on a laptop and in CI.

## Honest limits

- `platform/gl_context_sdl.cpp` has never been compiled: no SDL3 here, and no
  network to fetch it. It is the only file in the tree in that position, and CI is
  its first compiler.
- Nothing has drawn to a real surface. The GL device logic is tested; the driver is
  not. A green gate says the sequence is right, not that pixels appeared.
- No depth, no frustum clipping, no texture support: unchanged from M3 and still
  documented as absent rather than half-built.
