Both app loops now go through the RHI: `--frames` creates a device, clears and
presents each frame, and prints `presents=` and `digest=` next to the existing
`hash=`. `--window` does the same and resizes the chain when the window changes.

## Three decisions worth recording

1. **The bookkeeping is shared, not duplicated.** `SwapChainState` owns size
   validation, the clear/present counters and a digest over every submitted frame.
   The GL backend will drive the same class, so a test passing here tests the loop
   logic the game will actually run, not a mock of it.
2. **The digest exists so a present cannot silently stop happening.** Frame counts
   are cheap to fake; a hash over the sequence of clear colours and present indices
   is not. It also gives the future replay/golden tests a stable number to compare.
3. **`create_device` never returns null.** Asking for GL on a machine without it is
   not an error, it is a supported machine: the factory returns the headless device
   and logs which one was chosen. Null is reserved for a caller passing an invalid
   swap chain description, which is a bug in the caller.

## What is deliberately not here

`src/rhi/gl/` -- the OpenGL backend -- is **not written**, and that is a decision,
not an omission. This environment has no SDL3, no GL headers and no network to
vendor a loader, so a GL backend here would be several hundred lines that no
compiler has ever seen: exactly the "unverified work reported as done" that
`AGENT_PROTOCOL.md` forbids. The model for how it lands already exists in the repo
(`window_sdl.cpp` is compiled by CMake only when SDL3 is present); the backend will
follow it as `rhi/gl/gl_device_sdl.cpp`, which the fallback build skips for free
because its name ends in `_sdl.cpp`.

So: **the loop, the contract and the clearing path are real and tested; the pixels
are not there yet.**
